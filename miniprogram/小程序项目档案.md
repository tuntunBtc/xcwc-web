**待接服务端接口**：
- `GET /api/birds/by-code/{birdCode}`：真实实体资料（等备案域名 + request 合法域名）
- 服务端换取跳转凭证：`generate_urllink` / `generatescheme` / `wxacode.getUnlimited`（`access_token`、AppSecret 只在服务端，禁止落前端或文档）
- `code2session` + 手机号组件：后续登录（计费与额度需以官方最新规则核实）
- `wx.getWeRunData`：步数兑换叽分。2026-11-09 核对官方现行文档要点：
  - 基础库 ≥1.2.0；需 `scope.werun` 用户授权；**不支持 Promise 风格调用**（仅 success/fail/complete 回调）；需先 `wx.login`
  - 返回 `encryptedData` / `iv`（云开发另返回 `cloudID`，基础库 ≥2.7.0，有效期 5 分钟）；含过去 31 天步数，`stepInfoList[].timestamp` / `.step`；数据仅在用户主动进入小程序时更新
  - 解密在服务端：AES-128-CBC + PKCS#7，key = Base64_Decode(session_key)（16 字节），iv = Base64_Decode(iv)；校验 `watermark.appid` 与自身 AppID 一致、`watermark.timestamp` 时效性
  - `session_key` 由 `code2Session` 换取、只存服务端，不下发客户端；可能随 `wx.login` 刷新，可用 `wx.checkSession` 校验
  - 官方授权文档：`scope.werun` 一旦拒绝不再弹窗，直接进 fail，需 `wx.openSetting` 引导；授权弹窗文案取自《用户隐私保护指引》
  - 合规：MP 后台《用户隐私保护指引》须声明「收集微信运动步数」，用途写「步数兑换奖励」（官方示例用途之一）；提审版本隐私接口与指引不一致会被拦截或回收权限。以微信官方最新规则为准
- `POST /api/steps/redeem`：✅ **已实现**（见待办 16）。服务端用 `session_key` 解密、校验 watermark、按北京时间自然日幂等结算（复用 `PointsService.request_id` 幂等 + `operation='STEPS' AND target_id=<北京日期>` 同日守卫），前端只拿结算结果，不自行发分
- `POST /api/auth/wx-login`：✅ **已实现**。前端 `wx.login` 拿 code → 服务端 `code2session` 换 openid + session_key（仅存服务端）→ `ensureUserByOpenid` 建/取用户 → 下发本站 auth token；`session_key` 永不下发前端
