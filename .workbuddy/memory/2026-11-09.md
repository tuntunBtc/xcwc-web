## NFC 实体标签跳转链接形态（同日追加，官方文档核对）

- 用户给出旧入口样例 `https://www.jiuyouji.art/register.html?birdCode=<完整编码>`（编码为 25 个 ASCII 可见字符，真实值不落文档）。小程序无此类公开 URL；内部等价物是页面路径 `pages/adopt/adopt?birdCode=<编码>`，对外凭证有四类：URL Link 短链 `https://wxaurl.cn/<短码>`、明文 URL Scheme `weixin://dl/business/?appid=..&path=..&query=..`、加密 Scheme `weixin://dl/business/?t=<TICKET>`、小程序码 scene。
- 官方硬约束（2026-11-09 核对）：URL Link 由服务端 `POST /wxa/generate_urllink` 生成，path 不可带 query、必须是**已发布**小程序页面，query 最大 1024 字符；`expire_type` 0=失效时间点 / 1=失效间隔天数，**最长 30 天**，因此不能直接烧进长期实体标签；仅国内非个人主体，未发布报 85079。明文 Scheme 需 MP 后台声明，query 最大 512 字符且需 url_encode，**Android 不识别 Scheme、必须 H5 中转**，场景值 1286；加密 Scheme 场景值 1065。小程序码 `getUnlimited` 的 scene 最大 32 可见字符：`birdCode=<25字符编码>` = 34 字符会超限，**scene 只能放纯编码 25 字符**（现有 `parseBirdCode` 已支持无等号纯编码分支），小程序码永久有效、数量不限。
- 推荐路线 A（本轮结论）：**已发行标签地址原样保留**，把 `register.html` 改造成中转页（微信内用开放标签/云开发静态网站跳小程序，微信外用动态 Scheme 或 URL Link）；链接永不过期、零重制成本、可随时切换目标版本。路线 B（新标签直接写 URL Link）需重制标签且受 30 天有效期与「必须已发布」约束，不建议作为长期实体入口。新标签可加印小程序码作永久兜底。
- 官方资料冲突（以官方现行页面为准）：URL Scheme 指南页写每日打开上限 600 万，`generate_urllink` 服务端页写 300 万；第三方博客把 `expire_type` 写成「1 永久 / 2 指定有效期」，与官方不符。小程序码旧文档路径已失效，scene 限制取自官方接口文档与参考库，需以现行页面复核。基础库版本要求需核实。
- 当前不可生成正式凭证：小程序未提审发布、企业认证与 ICP 备案/HTTPS/request 合法域名在办理、`project.config.json` 仍为测试号。调试期用开发者工具「自定义编译条件」填启动参数 `birdCode=<编码>` 直接进领养页即可，无需任何跳转链接。后续需在 xcwc-api 增加服务端换取凭证接口（AppSecret 与 access_token 只在服务端，禁止落前端/文档）。

## web-view 嵌入 H5 可行性核查（同日追加，官方文档核对）

- 用户问领养页能否直接嵌网页 H5。结论：技术上能嵌，但**不建议**，决定性冲突是官方明文「客户端 6.7.2 起 `navigationStyle: custom` 对 web-view 组件无效」——web-view 页必然显示微信原生导航栏（返回/标题/胶囊），无法复现刚做好的沉浸式顶部；web-view 又会自动铺满整页、覆盖其它组件、每页仅一个，不能局部嵌入原生页。
- 官方硬限制（2026-11-09 核对 web-view 组件页 + 业务域名页）：个人主体/小游戏/小程序插件不支持；业务域名须 HTTPS + ICP 备案（新备案满 24 小时）+ 后台配置校验文件，不支持 IP，最多 300 个域名，配置后可打开任意子域名；「网页内 iframe 的域名也需要配置到域名白名单」；web-view 内仅支持有限 JSSDK 接口（图像/录音/设备/网络状态/地理位置/扫一扫/卡券等），**不含 wx.login、getPhoneNumber、getWeRunData、wx.request、storage、saveImageToPhotosAlbum**；`wx.miniProgram.postMessage` 只在小程序后退、组件销毁、分享、复制链接时触发，不能做实时桥接；网页与小程序间不支持 JSSDK 之外的通信。
- 项目侧事实：`dist/register.html` 是评审壳（`bjd-review` / `reviewbar` / `.phone` 手机外框）+ `srcdoc` `sandbox="allow-scripts"` 不透明源 iframe + MessageChannel/`accountRpc` 父页桥接 + `window.openai` widget 宿主（有 `?.` 降级），CSP 为 `default-src 'none'` 且资源域名靠 `__XCWC_ASSET_ORIGIN__` 替换。srcdoc 无域名可配白名单，属未验证高风险。`src/adopt/v1/adopt.js` 的资料与提交走 `accountRpc('adoptionContext'/'identity'/'adoptionPublic'/'adoptionMine'/'adoptionConfirm'...)`，不是独立页面，要嵌 web-view 必须先另做一份「去沙盒、去评审壳、直连后端」的独立 H5 落地页，等于重写。
- 能力缺口：步数兑换叽分、后续小程序授权 + 手机号登录、本机存储都只能在小程序原生页完成；H5 与原生两套存储/登录态不互通，数据会分裂。已取消的淘宝外链在 web-view 内同样不可跳。
- 建议：领养页（NFC 核心入口）保持原生；H5 只用于 NFC 中转页（已发行标签地址原样保留）；将来内容频繁变动、无需微信原生能力的商城活动页可单独开非 tab 的 web-view 页。纯 web-view 套壳易被拒属行业经验（官方运营规范未明文列条款），本工程已有 4 个原生 tab 页，风险相对可控；当前生产仍是公网 HTTP/IP 直连，备案与业务域名未齐前无法真机验证。本轮未修改任何文件。
